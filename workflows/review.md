# 交付检查

先过内容，再过格式。

| 检查 | 通过标准 |
| --- | --- |
| 岗位与主线 | 首屏能看到求职方向、阶段和两三条最强证据。通用版保留跨岗位能复用的能力，JD 版的要点能对应核心职责。 |
| 真实性 | 组织、任职时间、职务和动作与来源一致。个人与团队成果归属清楚。比率能追溯至同一统计口径。 |
| 扫读效果 | 重点已加粗，短标签指向具体动作。条目间少重复，一次扫读能明白成果发生在哪段经历。 |
| 交付格式 | 完整简历默认交付可编辑的 Word（`.docx`）。单条改写默认给可粘贴的条目。指定其他格式时按用户要求验收，HTML 只用于明确要求的网页。 |
| 隐私与边界 | 用户确认使用的姓名、联系方式和照片才会进入目标交付。公开样例使用虚构或明确获授权的材料。 |

## 生成和验收 Word

1. 使用当前环境的 Word 编辑工具或可用的 DOCX 库创建真正的 `.docx` 文件。保留可选中、可编辑的文本与标题。用户提供原 Word 时尽量复用其样式和结构。
2. 保存后打开或解析实际交付文件，确认正文与格式完整。有渲染条件时查看最终页面，检查页数、断行、加粗和留白。需要一页时先压缩重复和不相关的内容。
3. 交付 Word 文件及可访问的链接。若环境缺少渲染工具，说明版式检查范围。确实无法生成 Word 时，说明原因并明确将可复制的文字标作草稿。

交付时简短说明优先改了什么、采用哪份底稿或默认假设、有无待核实事实。投递正文保持干净，未确认的问题放在对话或单独的核对说明中。
