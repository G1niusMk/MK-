# resume-star | STAR 简历优化

把已有经历整理成一份招聘者能快速扫读的中文简历。从确认求职方向和基础资料开始，按岗位选证据，把 STAR 压缩成「本人动作＋可核对成果」，最后检查数字归属和成稿版式，默认交付**可编辑的 Word 简历（`.docx`）**。

**[快速开始](#快速开始) · [需要准备什么](#需要准备什么) · [工作流程](#工作流程) · [示例](#改写示例) · [常见问题](#常见问题)**

## 能做什么

| 你手里有 | 你要得到 | 使用路径 |
| --- | --- | --- |
| 经历素材或一份旧简历 | 一份面向某个方向的 Word 简历 | 全篇重构 |
| 旧简历与职位描述 | 对应单个岗位的 Word 投递稿 | JD 定制 |
| 一段经历和追加事实 | 更新后的单段内容 | 局部改写 |

## 快速开始

1. 把完整的 `resume-star` 文件夹放入目标项目的 `.agents/skills/`。项目里的文件路径应为 `.agents/skills/resume-star/SKILL.md`。多个项目通用可放入用户主目录下的 `.agents/skills/`。  [Codex Skill 文档](https://learn.chatgpt.com/docs/build-skills)
2. 在 Codex 中输入 `$resume-star`，附上现有简历或素材。
3. 回答影响成稿的缺项，已有信息由 Skill 直接提取。整份简历默认生成 `.docx`，也可以在请求中指定其他格式。

```text
用 $resume-star 帮我重写一份 HR 招聘与猎头的通用实习简历。
我会提供一份旧 Word 和一段校园活动材料。先核对缺项，
再把岗位相关的动作和结果放在前半页，尽量沿用原版式。
```

## 需要准备什么

**有旧简历**　直接附上，再告诉 Skill 目标岗位以及哪些材料是最新的。若要按 JD 定制，一并贴上职位要求。

**从零写**　给出目标岗位、求职阶段、希望显示的姓名或称呼，以及教育或最近工作背景。再提供两三段相关经历，写明时间、角色、你做过什么和已有结果。联系方式按你的意愿提供。

**只改一段**　给出原条目和新事实。数字最好同时给对象、时间范围和结果归属，例如「团队月度校内排名」或「个人暑期项目排名」。

第一次收到「帮我写简历」时，Skill 会先问目标岗位和可用材料。拿到材料后，只有关键缺项才会追问。例如「这 12 人是入群、进面还是最终入选？是你本人决定还是团队共同确定？」

## 工作流程

```text
读素材 → 选择改写路径 → 补齐基础与关键事实 → 排证据 → STAR 改写 → 核对并交付
```

- **先问清**　确认求职方向、阶段、教育或现职背景，以及成稿要展示什么。
- **再排序**　按岗位相关性、个人贡献和可核对的结果安排前后。
- **写成条目**　保留关键行动和结果，用短标签与加粗帮助扫描。
- **交付前看一遍**　查看数字口径、经历归属、页面前半部分和输出格式。

## 改写示例

虚构素材。「学校团队需要招新，我负责协调院系宣讲，收到 46 份有效报名。我与两位成员筛选材料、做短访谈。团队确认 11 人入选，我负责分组。」

> **校园招募与筛选**　协调院系开展宣讲并收集 **46 份有效报名**。与两名成员筛选材料、开展短访谈，团队选出 **11 人**，由我完成入组分配。

## 常见问题

**没有 JD 可以用吗？**  
可以。给岗位方向和求职阶段，就能做通用版。

**没有指标怎么写？**  
用能核对的产出、已完成的动作或收到的反馈。例如整理常见问题、完成筛选或提交建议。数字属于有证据时的加分项。

**需要提前准备完整简历吗？**  
不必。用角色、时间、本人动作和结果描述两三段经历即可起稿。已有的基础信息会直接复用。

**最终拿到什么文件？**

全篇重写、新写和按 JD 定制默认生成可编辑的 Word（`.docx`）。提供原 Word 时尽量沿用原版式。声明只要文案时交付可粘贴的正文，只有明确要求网页时才输出 HTML。
